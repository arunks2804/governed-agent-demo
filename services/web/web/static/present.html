Agentic AI Security

Why prompts are not security boundaries

The setup

An AI agent answers questions by writing SQL and Python. It can reach a shared database holding two fictional companies' orders — Acme (60 orders, 20,637.00) and Northstar (45 orders, 67,048.50). Users: Alice (Acme analyst), Victor (Acme viewer), Nina (Northstar analyst).

Each demo runs the same request in two environments. Unprotected has an over-privileged account and no checks. Protected enforces identity, tool validation, central policy, tenant isolation and runtime isolation. Every result below is produced live by the running services.

Each demo shows a deterministic probe (a fixed query that isolates the control). Where useful, you can also run the live AI to see what the model actually does.

Defense in depth

No unauthorized action should become an unauthorized database transaction. Prompts can be ambiguous, malicious, or injected; agents can make mistakes; tool outputs can be manipulated. Protection comes from identity, MCP authorization, tool permissions, runtime isolation, database authorization and audit logging — not from instructions in a prompt.
