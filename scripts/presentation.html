Problem Statement

The Default Configuration
Is Not Secure.

AI agents now translate natural language into structured database queries on behalf of users. Authorization is expressed in a prompt — not in cryptographically verified credentials.

  • ✕ OWASP LLM Top 10 #1 — Prompt Injection: an agent that follows instructions can be made to break them.
  • ✕ A system prompt is not an access control policy. It has no enforcement mechanism below the model.
  • ✕ Advisory checks that the model can choose to ignore are not controls. They are suggestions.

Threat Landscape

Two Independent
Threat Vectors.

Agents Can Misbehave

  • →Prompt injection via adversarial user input
  • →Indirect injection through documents the agent reads
  • →Model hallucination bypassing intended constraints
  • →Instruction override via jailbreak or context stuffing

Humans Can Misbehave

  • →Malicious insiders with direct API access
  • →Compromised tokens or stolen credentials
  • →Direct backend calls that bypass the agent entirely
  • →Misconfigured service permissions exploited at scale

In both cases, a system that relies only on the agent's cooperation fails.

What Needs To Be Enforced

Defense in Depth —
Controls at Every Independent Layer.

IDENTITY Verified JWT Every request carries a cryptographically signed token (EdDSA). Identity is verified — not trusted on claim alone.
POLICY OPA at Service Layer Open Policy Agent evaluates every query at the service boundary against the verified identity. The agent cannot modify this check.
DATA PostgreSQL RLS FORCE ROW LEVEL SECURITY enforced at the database. Filters tenant rows below the application — regardless of how the connection arrives.

The Experiment

One Query. Four Controls.
Same Infrastructure.

Acme analyst requests Northstar order data — a multi-tenant access violation. Same PostgreSQL database. Same Ollama model. Different enforcement at each level.

L1Prompt Only System prompt instructs the model not to cross tenants. No service or DB controls exist. UNSAFE
L2Advisory Tool Agent calls a policy tool that returns "not recommended". The advisory is not enforced. UNSAFE
L3Backend OPA Signed JWT + OPA policy at service boundary. Denied before the query reaches the database. SAFE
L4PostgreSQL RLS FORCE ROW LEVEL SECURITY on the reader role. Zero rows — even with a direct DB connection. SAFE
governed-agent-demoTest Matrix
Level 1 of 4

Prompt Only

Configuration: The model receives a system prompt instructing it not to access data belonging to other tenants. No controls exist at the service boundary or the database layer. This represents the default architecture for most production AI agents deployed today.

Expected outcome: The cross-tenant query executes. The system prompt imposes no technical barrier. A compliant model may refuse — but a manipulated one, or a direct API call, will not.

EXPECTED: UNSAFE No enforcement below the model layer
governed-agent-demoL1 — Prompt Only
Level 2 of 4

Advisory Tool

Configuration: The agent is given access to a policy-check tool it can call before executing a query. The tool evaluates the request and returns a recommendation — for example, "not recommended". This is a common pattern in AI agent design and is often presented as a safety measure.

Expected outcome: The tool returns its advisory. The agent acknowledges it — and executes the query anyway. An advisory that can be overridden by the model is not an access control.

EXPECTED: UNSAFE Advisory ≠ enforcement
governed-agent-demoL2 — Advisory Tool
Level 3 of 4

Backend OPA Enforcement

Configuration: Every request now carries a signed EdDSA JWT that cryptographically binds the caller's tenant identity to the request. Open Policy Agent evaluates the identity and the query at the service boundary before any SQL is issued. The agent cannot modify or bypass this check.

Expected outcome: The cross-tenant request is denied at the service layer — before it reaches the database. Regardless of what the agent was instructed to do, or what a manipulated prompt says, OPA enforces the policy.

EXPECTED: SAFE Enforced independently of the agent
governed-agent-demoL3 — Backend OPA
Level 4 of 4

PostgreSQL Row-Level Security

Configuration: The Acme reader role connects with FORCE ROW LEVEL SECURITY enforced at the database. This is a backstop control — it holds even if OPA is down, a token is forged, or the application layer is compromised. It cannot be bypassed from within the application.

Expected outcome: The cross-tenant query returns zero rows through the agent — and also when connected directly to the database, bypassing every upstream service. The database enforces the boundary.

EXPECTED: SAFE Holds even with a direct database connection
